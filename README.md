# Roadkill Turret

Тестове завдання Unity Developer - core-механіка аркадної гри: гравець керує туреллю, встановленою на автомобілі, що рухається вперед по рівню. Задача - доїхати до фінішу, знешкодивши якомога більше ворогів, не втративши все ХП автомобіля.

## Геймплей

- Тап/клік по екрану - старт руху автомобіля
- Утримання й переміщення пальця/курсора по екрану - наведення турелі
- Турель стріляє автоматично, поки гра триває
- Вороги стоять у idle-стані вздовж дороги; при наближенні авто починають бігти до нього і завдають шкоди при контакті
- Перемога - доїхати до фінішної лінії з ХП > 0
- Поразка - ХП автомобіля впало до 0
- Після Win/Lose - тап для рестарту рівня (генерується нова випадкова розстановка ворогів)

## Технології

- **Unity 6000.3.8f1** (URP)
- **VContainer** - dependency injection
- **UniTask (Cysharp)** - асинхронна логіка (ігровий цикл, очікування win/lose умов через `UniTask.WhenAny`)
- **New Input System** - уніфікована обробка миші/тачу через `Pointer`
- **Cinemachine** - камера, що слідує за автомобілем
- **TextMeshPro** - UI

## Архітектура

- **`Car`** - центральний координатор автомобіля: об'єднує рух, турель і здоров'я, запускає/зупиняє їх у відповідь на події `GameFlowController`. Інші компоненти (`CarMovement`, `TurretAiming`, `TurretShooting`) нічого не знають про глобальний стан гри - лише виконують команди
- **`GameFlowController`** - головний ігровий цикл (очікування тапу -> старт -> очікування результату рівня -> показ Win/Lose -> рестарт через перезавантаження сцени), реалізований через `UniTask`
- **`LevelController`** - визначає результат рівня через `UniTask.WhenAny`, паралельно очікуючи або смерть автомобіля, або досягнення фінішу
- **`LevelGenerator`** - процедурно генерує дорогу потрібної довжини і розміщує фініш
- **`EnemySpawner`** - розставляє ворогів вздовж рівня з мінімальною дистанцією між ними та відступами від старту/фінішу, з обмеженою кількістю спроб пошуку вільного місця (кількість ворогів масштабується від довжини рівня)
- **`Health` / `IDamageable`** - єдиний перевикористовуваний компонент здоров'я, спільний для автомобіля і ворогів
- **`HealthBar`** - узагальнений UI-компонент, що працює з будь-яким `Health` (world-space над ворогами, показується лише після першого влучання; на автомобілі - постійний HUD-елемент)
- Кулі використовують **object pooling**; вороги - kinematic-об'єкти з простим векторним рухом до цілі (NavMesh свідомо не використовувався - рівень без перешкод, тому не потрібен)
- Комунікація між системами - через C#-події, без жорстких прямих залежностей між незв'язаними класами

## Як запустити

1. Unity **6000.3.8f1** з URP
2. Відкрити `Assets/Game/Scenes/SampleScene.unity`
3. Play - тап/клік по екрану для старту

## ⏱ Орієнтовний час виконання

Завдання виконувалось протягом 4 днів: сетап проєкту і базовий рух автомобіля - у п'ятницю ввечері, основна розробка - на вихідних кількома сесіями з перервами, фінальне доопрацювання і полірування - у понеділок ввечері. Орієнтовно - **16-22 години** сумарного активного часу розробки.
